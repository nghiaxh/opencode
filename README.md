# Opencode config

Global opencode configuration for commands and settings.

## Install

```bash
cd ~/.config/opencode
git init
git remote add origin https://github.com/nghiaxh/opencode.git
git fetch origin
git reset --hard origin/main
```

## Update

Edit config directly at `~/.config/opencode/`, then commit and push:

```powershell
cd $HOME\.config\opencode
git add -A
git commit -m "chore: update config"
git push
```

## Structure

```
opencode.jsonc              # Server and project config
cli.json                    # Terminal client preferences, owned by the TUI
AGENTS.md                   # Always-on instructions, the only file auto-loaded
commands/lazy-commit.md     # /lazy-commit
commands/lazy-audit.md      # /lazy-audit
commands/lazy-review.md     # /lazy-review
commands/lazy-debt.md       # /lazy-debt
service.json                # Generated by the v2 service, gitignored
```

## Skills

This repo tracks no skills. Every skill is installed with `npx skills` into
`~/.agents/skills/`, which OpenCode discovers automatically, so a fresh clone of
this repo starts with no skills at all.

### Install

```powershell
$env:DISABLE_TELEMETRY=1
npx skills find <query>                              # search the registry
npx skills add <owner/repo> --skill <install name> -g -a opencode --copy -y
npx skills list -g -a opencode                        # what is installed
npx skills update                                    # refresh every install
```

`--skill` takes the **install name**, which is the `name:` field in the skill
frontmatter, not the folder name in the source repo. `-g` is global, `-a opencode`
targets this agent, and `--copy` is required because a symlink breaks git
tracking on the installed files.

A skill's **ID** is its installed directory name. The frontmatter `name` is only
a display label, so a repo folder called `react-best-practices` that declares
`name: vercel-react-best-practices` is loaded as `vercel-react-best-practices`.

### Hiding a skill

Add this to the skill's frontmatter to keep it out of the model's advertised
list while leaving it loadable by ID:

```yaml
metadata:
  opencode/autoinvoke: false
```

`npx skills update` overwrites the file and drops the flag, so re-apply it after
an update. `slash: false` does the same for the interactive command palette.

### Design skills

Design skills are not installed by default. The upstream set is
[leonxlnx/taste-skill](https://github.com/leonxlnx/taste-skill) (MIT), which
ships 14 skills per skill folder, all named `SKILL.md` and nothing else:

```powershell
npx skills add https://github.com/Leonxlnx/taste-skill --skill design-taste-frontend -g -a opencode --copy -y
```

Install one, not the whole repo. They enforce conflicting aesthetics on purpose,
so more than one advertised at a time produces incoherent output. Load at most
one design skill per task.

## Reload

- Command files and config reload on save, no restart needed.
- `AGENTS.md` edits are detected before the next model request and sent as an
  instruction update.
- Newly installed skills need a restart or a new session before they show up.
- Removing every `AGENTS.md` tells the session its previous instructions no
  longer apply.
